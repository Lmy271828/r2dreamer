# 涌现探针套件（Emergence Probes）：学习顺序的量化分析设计

> 目标：基于人类策略先验作为**评估透镜**，量化自博弈过程中能力涌现的
> 顺序——从视觉表征，到（L2/L3 再议：基础攻防与长程节奏），到 meta 层
> 的卡组比较与体系聚类。
>
> 纯度边界（2026-10-30 定）：人类策略体系**只出现在评估与分析侧**；
> 训练信号保持 ±1 终局奖励与零先验采样（purity_ladder.md）。探针可以
> 用探针全知状态，训练不用。

## 1. 数据保存：三层结构

确定性引擎（seed 决定卡组/抽牌序/物理）是整个方案的地基：**seed + 动作
日志 = 无损记录**，任何一局可在模拟器内逐 tick 重放（V4"元数据 + 模拟器
内回放"的思想吸收在此，作为 T0）。

| 层 | 内容 | 大小/局 | 性质 |
| --- | --- | --- | --- |
| T0 无损底座（永远存） | 局清单：seed、双方卡组、episode_id、每决策步扁平动作索引、终局奖励/原因 | ~几十 KB | 完全无损，可离线重放/重算任何细节 |
| T1 视频（触发式） | screenrecord 流抽 2 fps 低帧视频（内存中已有帧，零额外采集） | ~2MB/分钟 | 肉眼索引；按触发规则存 |
| T2 分析工件 | 冻结 checkpoint、encoder 嵌入样本、探针指标序列 | 按需 | 纵向对比用 |

### T1/T2 触发规则（不可再生性 × 分析价值）

① score / 局长极端局（最速攻、最持久）；② 首次事件（首次技能释放、
首次成功防守反击）；③ 快照激活/刷新边界局；④ 每 N 局固定采样一局作
"时代切片"。其余局只留 T0。

### 落盘布局

```
runs/<id>/episodes/ep_<n>.jsonl   # T0 清单 + 逐步动作
runs/<id>/videos/                 # T1 触发式视频
runs/<id>/snapshots/ckpt_*.pt     # T2 周期性归档（每 ~30min + 每次快照刷新前）
runs/<id>/probes/probes.jsonl     # T2 探针指标序列
```

注：当前快照是被覆盖刷新的（load_state_dict），历史版本不保留——学习
顺序分析的第一实现项即周期性归档。

## 2. 探针定义

### L1 视觉表征层（已认同）

冻结 encoder 特征 + 线性探针，读**探针可得真值**：
我方圣水、双方塔血、场上单位数（分阵营）。
输出：各量的探针精度曲线（R²/acc vs updates）——视觉表征"看懂战场"
的时间点序列。

### L2 基础攻防（**再议**，暂不注册）

曾提案：固定剧本对局中量出牌率/防守延迟/位置熵。暂缓原因与重开条件：
待 T0 动作日志落地后先离线试算几局，确认这些量在 T0 上可稳定计算、
且对热身期噪声不敏感，再补注册。

### L3 长程节奏（**再议**，暂不注册）

曾提案：防守反击率、圣水溢出率、局长-胜负相关。暂缓原因同 L2
（定义的稳定性和可计算性待 T0 数据验证）。

### L4 meta 层（已认同）

两条：
1. **V 排序演化**：V(s_open, d) 对固定卡组候选集的排序，随 checkpoint
   序列的 Kendal-τ 变化——排序何时稳定（配 KL 平台期门禁）即 meta 观
   形成时点；
2. **卡组体系聚类**：DeckEncoder（s4_deck_encoder.md）嵌入的聚类结构，
   与人类卡组类型学（beatdown/循环/桥 spam 等）做**外部标注对齐**——
   人类分类学只当量尺（评估），不进训练。

## 3. 实施排期

| 步骤 | 内容 | 依赖 |
| --- | --- | --- |
| 1 | T0 动作日志 writer（env 侧，per-episode jsonl） | 无，最小改动 |
| 2 | snapshots 周期归档（trainer 侧） | 无 |
| 3 | L1 探针脚本（冻结 encoder + 线性探针 + 探针真值读取） | 1/2 |
| 4 | L4 打分器（依赖 S4 DeckEncoder + V 条件化） | S4-lane |
| 5 | L2/L3 定义验证（T0 离线试算） | 1 |
