# 纯度阶梯（Purity Ladder）：像素-only 自博弈的分级验证路线

> 总目标（2026-10-30 定）：**在只有对 arena 的视觉观测的前提下，不依赖外部
> 统计先验，从 0 自博弈逼近最佳策略。**
>
> 工作纪律：今后每次往训练信号里加东西，先过一遍——"这信息玩家从画面或
> 规则里能知道吗？"能 → 接口（允许）；不能 → 先验（禁止，或标注为脚手架
> 并排入移除）。有消融价值的按 ablation_hier_action_head.md 的预注册规程。

## 什么算先验（禁止），什么算接口（允许）

| 判定 | 内容 |
| --- | --- |
| ❌ 先验 | 人类回放数据（datasets/build_ppo_deck_pool）、人类精选卡组（focus_decks_20）、探针内存读数作为模型输入（elixir 数值、hand_ids、deck_ids、opp_deck_ids）、V4 catalog 蒸馏材料 |
| ✅ 接口 | 终局 ±1 奖励、动作合法性掩码（环境规则，AlphaStar 合法动作集先例）、像素里可见的一切（战场、手牌区、圣水条、下一张预览） |

## 阶梯

### P0（当前，实弹中）：像素战场 + 探针侧通道

obs = image(战场 128×176) + elixir/elixir_rate(探针) + hand_ids(探针) +
action_mask(引擎规则)。世界模型/两级动作头/技能位在此配置下验证（run
1030_004637_m4_cardvec）。

**角色**：对照基线。P1 的消融对象。

### P1（下一里程碑）：底部 UI 并入观测，删探针侧通道

1. **采集**：capture.py 已加 `BOTTOM_CROP=(0,1620,1080,1920)` 标定矩形与
   `capture_bottom()`（默认降采样 120×648，卡面纵横比无失真）。实测该条
   含：4 张手牌卡面+费用角标、卡牌可用性灰化（圣水不足的卡视觉上变灰——
   affordability 本身是视觉特征）、圣水条（填充比例即数值）、下一张预览。
2. **模型侧**：
   - 手牌候选嵌入：从底部条裁 4 个卡面 patch → 小 CNN → 候选嵌入，替换
     CardEmbeddingTable 查表（点积卡头结构不变，换嵌入来源）；
   - 圣水：小回归头从圣水条 patch 读数值（或直接把底部条整条进 encoder）；
   - 删除 obs 键 elixir/elixir_rate/hand_ids；
3. **保留**：action_mask（规则接口），但 affordability 判定留在 env 规则
   层，不作为模型输入通道。

**预注册判据**（P1 vs P0 消融）：世界模型损失收敛速度比、episode/score
斜率比、卡头选卡与手牌真值的对齐率（env 有真值可对账）。P1 样本效率必然
先降——降幅就是"侧通道值多少样本"的测量值，是实验产出不是失败。

### P2：去动作掩码

掩码删除，非法动作由 env 降级 WAIT（已有）。对照"掩码是加速器还是
必需品"。预计学习变慢但可行——预注册：若 200k step 内 score 斜率 < P1
的 1/3，判定掩码为必需接口（保留），否则视为可去的脚手架。

### P3：零先验对手池

ε-greedy 联赛的 PFSP 权重来源 = **自博弈战绩表**（league_stats.jsonl）+
历史策略快照，不用人类统计。discard：focus_decks_20、build_ppo_deck_pool
产物（人类先验，本目标下禁用）。对手卡组分布 ρ̂ = 自博弈涌现混合，
V(s,d0) 的边缘语义随之（见 league 设计讨论：d0 侧保持 uniform-122 保
评分覆盖，d1 侧即 ρ̂）。

**自博弈的视角对称性（2026-10-30 定案）**：像素自博弈采用**逐局换边**
（`_swap_next`，奇偶局交换 deck0/deck1），不采用双视角渲染。
- 撤销"同帧翻转派生对方视角"：单位配色、血条/塔归属、特效朝向等语义
  绑定在渲染里，几何变换不可还原（探针也无渲染侧视角切换接口；
  perspective.py 的 flip 只作用于结构化观测坐标，属 V4 基线）。
- 换边的正确语义：不是"看对方屏幕"，而是**角色交换后仍坐本方规范视角**
  （己方永远在下方/己方配色）——与部署视角完全一致，零视角歧义；
  代价是同一局只能成为一侧的训练样本（数据效率减半），两侧经验靠
  奇偶局交替覆盖。
- 自博弈只需一个 guest：引擎是双侧并行环境，owner-1 的动作/掩码/FAIR
  视图经同一条探针连接从同一引擎状态派生；两份的是 agent 侧的循环
  记忆流（在线 + 冻结副本），与 guest 数量无关。

## S4 修订

原 S4（deck 条件 critic）降级：自博弈目标下 opp_deck_ids 无泄露问题也
无需求（对手即自己生成的抽样）。保留 deck 条件作为**可选消融**（评分
覆盖用，deck_ids 属于"玩家知道自己的卡组"的灰色地带），不进主线。
主线下一里程碑 = P1。
